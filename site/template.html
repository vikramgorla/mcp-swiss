    Install

    Pick your app. Every option runs the same server; nothing else to configure.

    Download mcp-swiss.mcpb and open it. Claude Desktop installs it for you.

    Or add this to claude_desktop_config.json (Settings, Developer, Edit Config) and restart Claude:

    {
  "mcpServers": {
    "swiss": {
      "command": "npx",
      "args": ["-y", "mcp-swiss"]
    }
  }
}

    The file lives in ~/Library/Application Support/Claude/ on macOS, %APPDATA%\Claude\ on Windows and ~/.config/Claude/ on Linux.

    claude mcp add swiss -- npx -y mcp-swiss

    It's available from your next session.

    Add this to .cursor/mcp.json in your project, or ~/.cursor/mcp.json for every project:

    {
  "mcpServers": {
    "swiss": {
      "command": "npx",
      "args": ["-y", "mcp-swiss"]
    }
  }
}

    Install in VS Code VS Code Insiders

    From a terminal:

    code --add-mcp '{"name":"swiss","command":"npx","args":["-y","mcp-swiss"]}'

    Or share it with your team in .vscode/mcp.json:

    {
  "servers": {
    "swiss": {
      "command": "npx",
      "args": ["-y", "mcp-swiss"]
    }
  }
}

    Any app that speaks MCP over stdio works with this command:

    {
  "command": "npx",
  "args": ["-y", "mcp-swiss"]
}

    Windsurf reads it from ~/.codeium/windsurf/model_config.json under "mcpServers". Cline reads it from VS Code settings under "cline.mcpServers". Requires Node.js 20 or later.

    {
  "mcpServers": {
    "swiss": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "vikramgorla/mcp-swiss"]
    }
  }
}

    Images are on Docker Hub (vikramgorla/mcp-swiss) and GitHub (ghcr.io/vikramgorla/mcp-swiss).

    npx -y mcp-swiss --http

    Serves Streamable HTTP at http://127.0.0.1:3000/mcp with a /health check. Change it with --port and --host. Listening on anything other than localhost requires MCP_AUTH_TOKEN and MCP_ALLOWED_HOSTS; sessions are capped by MCP_MAX_SESSIONS (default 64).

    How it works

    Listing {{TOOL_COUNT}} tool schemas would cost about {{FULL_TOKENS}} tokens in every conversation. So by default the server lists five tools, about {{SEARCH_TOKENS}} tokens, and the assistant searches for the rest:

    swiss_search_tools
    Takes the task in plain words, typos included, and returns the best-matching tools with their parameters.
    swiss_call_tool
    Runs any tool by name after checking its arguments, and suggests the right name if one is mistyped.
    swiss_list_modules
    The whole catalogue, module by module.
    get_connections, get_departures
    The two most-used tools, ready without a search.

    The server also tells the assistant, when it connects, which modules exist and to search before giving up. Every tool only reads public data, so apps can approve calls without asking you each time.

    Options

    Add to argsWhat you get
    nothingSearch mode, as above. Recommended.
    --modules transport,weatherOnly those modules, with their tools listed directly. --list-modules shows all {{MODULE_COUNT}}.
    --preset commuterA ready-made set: {{PRESETS}}.
    --mode fullAll {{TOOL_COUNT}} tools listed directly. Fine in apps that already load tools on demand, such as Claude Code.
    --pin get_weather,geocodeDifferent tools next to the search tools, or --pin none for only the three.
